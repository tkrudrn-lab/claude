# 자동화 에이전트 설계 v01 (2026-10-25)

맥스튜디오를 24시간 본진으로 두고, 5개 사업 작업을 에이전트가 **초안까지** 만들어 아이폰·노트북으로 보내는 구조.
사람은 확인하고 보내기(발행·발송·게시)만 한다. 이 문서는 **설계**다. 구현 계획은 도메인별로 따로 세운다.

## 전제 (2026-10-25 현재)

- 맥스튜디오는 도착했지만 **아직 이 노트북에서 SSH로 못 들어가고, D: 복사도 안 됐다.** 그래서 공용 뼈대와 블로그는 **윈도우에서 먼저 짓고** 경로는 `D:\` 값으로 시작한다. 스크립트는 Python·curl만 써서 맥에서 그대로 돈다. 스케줄(launchd)과 맥 전용 검증은 반입 뒤(아래 체크리스트).
- 맥은 **FileVault 끄고 자동 로그인**(사용자 결정). 재부팅 뒤에도 GUI 세션이 떠 있어야 헤드풀 Chrome(네이버)·LaunchAgent가 돈다.
- 아이폰에는 Claude 앱, 텔레그램. 노트북(Windows)은 반입 뒤 SSH·SMB로 맥에 붙는 클라이언트.

## 원칙

**목표**
- 사용자가 키워드·품목·E번호 하나를 던지면 초안이 완성되어 폰으로 온다.
- 밤에 돌아가는 긴 작업(생성·렌더·리서치)은 맥이 하고, 끝나면 알린다.
- 기존 자산(naver-blog 툴, nuritech 상세페이지 파이프라인, 서천 파이프라인, 릴스 기획안) 위에 얹는다. 새로 만드는 건 빈 자리만.

**하지 않는 것**
- 발행·발송·게시·결제·삭제를 에이전트가 하지 않는다. 승인선은 아래 표. `naver-blog` 규칙 2(PUBLISH_GUARD)를 전 도메인으로 확장한다.
- 인스타그램 자동 게시·댓글·DM·팔로우 자동화 (브라우저 봇) — 계정 정지가 곧 채널 상실.
- LinkedIn 등 로그인 뒤 데이터 스크래핑으로 바이어 리스트 만들기.
- 피클볼 코드·스캐폴딩 (착수 전, [pickleball/CLAUDE.md](../domains/pickleball/CLAUDE.md) 규칙).
- 대시보드·오케스트레이터를 먼저 만들지 않는다. 스킬 하나가 돌고 난 뒤에.
- Claude API 키 사용 금지 (구독 세션만). 생성 툴(Higgsfield·ElevenLabs·Kling) 키는 지금처럼 쓴다.

**실패로 치는 것**
- 지어낸 사실(가격·인증·규격·연락처·개체 상태)이 초안에 섞여 나가는 것.
- 사용자가 모르는 사이에 뭔가 밖으로 나가는 것.

## 공용 뼈대 (platform)

### 실행 단위

도메인 폴더 하나 = Claude Code 세션 하나. 팀 멤버 정의([domains/*/CLAUDE.md](../domains))는 그대로 두고,
실행은 Claude Code 네이티브로 옮긴다.

| 개념 | 구현 |
|---|---|
| 반복 작업 1개 | 스킬 1개 (`.claude/skills/<작업>/SKILL.md` 또는 기존 `.claude/commands/`) |
| 팀 멤버 1명 | 서브에이전트 1개 (`.claude/agents/<멤버>.md`) — 스킬이 필요할 때만 부른다 |
| 도메인 메모리 | 해당 폴더 `CLAUDE.md` + `docs/` (지금 방식. "다음 세션은 기억 못 한다, 파일로") |

agent-teams 앱은 맥에 있으면 연결하고, 없어도 이 설계는 돈다.

### 트리거 2종

| 방식 | 언제 | 어떻게 |
|---|---|---|
| 손으로 | 키워드·품목·E번호를 줄 때 | 아이폰 Claude 앱 → 맥에서 Remote Control 켜 둔 세션. 또는 노트북 SSH → `claude` |
| 시계로 | 매일 같은 일 | `launchd` (`~/Library/LaunchAgents/com.hermes.<job>.plist`) → `python ~/hermes/platform/jobs/<job>.py --notify` 또는 `claude -p "/스킬 …"` |

v01 스케줄 잡은 **2개만**: `catalog`(미디어 카탈로그 갱신, 매일 밤), `inbox`(누리텍 받은편지함, 매일 아침).
나머지는 전부 손으로. 돌려 보고 매번 똑같이 치는 명령이 생기면 그때 스케줄에 올린다.

### 알림

텔레그램 봇 1개, 스크립트 1개: `python platform/jobs/notify.py --job <잡> "<한 줄>" [--file 첨부]`.
- 모든 스킬의 마지막 단계, 모든 스케줄 래퍼의 끝에서 호출. **실패도 보낸다. 스케줄 잡은 0건이어도 보낸다**("실행됨 · 새 메일 0") — 안 돈 것과 할 일 없음을 구분하는 유일한 수단.
- 첨부는 50MB까지 파일로, 넘으면 경로만.
- 토큰은 `~/.config/hermes/telegram.env`. 저장소에 넣지 않는다.
- 텔레그램인 이유: 아이폰·윈도우·맥 셋 다 같은 채널, 영상 첨부 가능, 봇 만드는 데 5분.

### 미디어 카탈로그

사진·영상을 "찾는" 작업이 블로그·릴스·미디어아트에 공통이라 한 번만 만든다.

- `~/Media/<폴더>/_catalog.csv` — 파일명 · 절대경로 · 촬영일 · 길이/해상도 · 설명(선택).
- `platform/jobs/catalog.py` (Pillow + ffprobe). 열은 `rel_path · taken · duration_s · width · height · size_mb · note` 7개, `rel_path`는 `/` 구분자라 맥으로 옮겨도 행이 유효. 새 파일만 추가, 사라진 파일 행은 삭제, `note`는 보존, 원본은 건드리지 않는다. 폴더에 `.nocatalog` 파일을 두면 그 폴더는 건너뛴다.
- 설명 열은 **비워 두고 시작**한다. 블로그·릴스 작업 중 실제로 Read로 본 사진만 채운다. 수백 장을 미리 보는 건 안 한다.
- 스킬은 카탈로그에서 후보를 고른 뒤 **반드시 Read로 실제 확인**(기존 "파일명 추측 금지" 규칙).
- 선례: [비바리움_소스목록_20261024.md](../domains/shop/비바리움_소스목록_20261024.md).

## 도메인별

### 1. shop — 블로그 (하이다이노)

**입력** — 키워드 1개 + 주제 프리셋 + 추가 조건 한 줄. 예: `/write 성북구 크레스티드게코 분양 --topic 분양 "루비 모프 2마리, 픽업만"`.
주제 프리셋은 `naver-blog/data/topics/<주제>.md`에 한 번 적어 두고 재사용한다 (분양 / 사육 정보 / 비바리움 / 매장 방문 / 이소포드 — 기존 체크리스트 5종과 1:1).

**사실은 입력 줄에서 온다.** 분양 글의 개체 사실 8종(모프·해칭일·무게·성별·꼬리·먹이·분양가·픽업)은 사진에도 `profile.md`에도 없으니 사용자가 입력 줄에 넣는다 — `topics/분양.md`가 그 양식. 빠진 항목은 **지어내지 않고 `[확인 필요]`로 두고 임시저장**, 알림에 "확인 필요 n곳" 경고. 협찬 여부가 입력에 없으면 "아님"으로 두지 않고 **되묻는다**(규칙 3·4 유지). 개체 장부 파일은 만들지 않는다 — 입력 줄로 모자라면 그때.

**흐름** — 기존 `/write`에 4단계를 더한다.

1. 카탈로그에서 키워드·주제에 맞는 사진·영상 후보 → Read로 확인 (기존 재료 확인·모자이크 단계 유지)
2. 초안 **1,500~1,800자** (`data/trends.md` 기본값을 1,800~2,500에서 바꾼다. 정보성 글 상한은 사용자 확인)
3. **썸네일 1장** — `naver-blog/scripts/thumb.py`: 고른 사진 1장 + 제목 핵심어 2줄, 1:1 1080px, 템플릿 1개. 첫 이미지 블록에 넣어 대표 이미지가 되게
4. 임시저장 (규칙 7 "승인 후 임시저장"을 **임시저장까지 자동**으로 완화. 발행 가드는 그대로)
5. `notify.py`: 제목 · 글자 수 · 썸네일 첨부 · "네이버 앱 저장 글에서 확인"

**새로 만드는 것** — topics 프리셋 5개, `thumb.py`, 카탈로그 연동, trends 값, 알림 단계.
**맥 이전 시** — Playwright `channel: 'chrome'`이라 맥에 Chrome 필요. `naver-profile` 로그인 세션은 맥에서 `/setup-login` 1회 다시.

## 맥 반입 체크리스트 (사용자 수작업 + 1회 세션)

순서대로. 끝나면 `paths.env`와 라우터·메모리의 `D:\` 경로를 같은 턴에 갱신한다.

1. 시스템 설정 — 에너지(잠자기 방지·네트워크 깨우기·정전 후 자동 시동) · 공유(원격 로그인·화면 공유·파일 공유 + Windows 파일 공유) · **FileVault 끔 · 자동 로그인 켬** · HDMI 더미 플러그 · UPS
2. Tailscale 설치, 이름 `mac-studio`, 키 만료 해제. 노트북에서 `ssh mac-studio` 확인
3. Chrome · Claude Code 설치, 구독 로그인. 아이폰 Claude 앱에서 Remote Control 확인
4. D: → `~/Media/` rsync (이전 안내 명령). 두 번째 실행에서 0건이면 끝
5. hermes 폴더 복사 → `~/hermes`. `nuritech` → `~/nuritech`, `hidino-reels` → `~/hidino-reels`
6. `~/.config/hermes/` 토큰·`paths.env` 맥 값으로
7. `naver-blog` — `npm install`, `/setup-login` 1회 (네이버 로그인 세션 재생성)
8. Gmail — 커넥터가 globalnuritech@gmail.com 에 붙는지 확인. 안 되면 Mail.app에 그 계정 추가
9. launchd 2개 등록(`catalog`·`inbox`) → 그날 밤 "실행됨" 알림이 오는지 확인. **plist에 `EnvironmentVariables` → `PATH`에 Homebrew(`/opt/homebrew/bin`)를 넣고 `python3`은 Pillow가 깔린 절대경로로** — 기본 PATH엔 ffprobe가 없고 Apple python엔 Pillow가 없어서 카탈로그 필드가 조용히 빈다(알림에 "ffprobe 없음"이 뜨면 이것). `paths.env`의 `~/Media/...`는 경로마다 풀린다
10. 라우터·인덱스·메모리의 `D:\` → `~/` 갱신
